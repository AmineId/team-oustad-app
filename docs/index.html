lib/

      
Architecture

      
Trois couches, avec un fichier « barrel » à chaque niveau : on importe services/services.dart, pas les fichiers un par un. Pas de Provider ni de Bloc : un ChangeNotifier plus un InheritedWidget pour le thème et la langue.


lib/
├─ main.dart            Firebase, notifications, FCM, anti-capture, thème et langue
├─ core/                aucune UI
│  ├─ config/           AppConfig : l'URL selon l'environnement
│  ├─ services/         ApiService (presque tous les appels backend), AuthService (biométrie),
│  │                    FCM, notifications locales, vérification de version, langue, boutique, bannières
│  ├─ models/  theme/  utils/
│  └─ l10n/             traductions écrites à la main (fr / en / ar), pas d'ARB
├─ screens/             auth · admin · member · common, SplashScreen route selon le rôle
└─ widgets/             common (Modern*), responsive (grille, layout), platform (desktop, montre)

      
Ajouter une traduction

      
Ajoute la clé dans les trois tables de app_localizations.dart (fr, en, ar), puis un getter. Une clé absente s'affiche telle quelle à l'écran.

    


    

      
semantic-release

      
Release

      
La version n'est jamais modifiée à la main : le type de commit décide. Le pipeline réécrit pubspec.yaml et version-metadata.json, signe l'AAB, le publie sur le Play Store et envoie la version au serveur, qui sert la vérification de version dans l'app.

      

        
feat(store): panier
fix: crash check-in

        
↗↘

        

          
staging→ 1.x.y-beta.N, construit en pprod, Play Store « beta »

          
main→ 1.x.y, construit en prod, release de production

        

      

      

        

          
Préfixe du commitEffet sur la version

          
            
feat:mineure : 1.2.0 → 1.3.0

            
fix: perf: refactor: revert:correctif : 1.2.0 → 1.2.1

            
feat!: ou BREAKING CHANGEmajeure : 1.2.0 → 2.0.0

            
docs: chore: style: test: ci: build:aucune release

          
        

      

      
Les PR vers main ou staging lancent flutter analyze --fatal-infos : un simple « info » de l'analyseur fait échouer la PR.

    


    

      
Sans Mac, avec xtool

      
Tester sur iPhone

      
Flutter ne compile pour iOS que sur macOS. GitHub compile donc un .ipa non signé, et xtool le signe avec ton Apple ID puis l'installe en USB depuis WSL.

      
    
        
  1. Brancher l'iPhone dans WSL (PowerShell admin, à chaque branchement)

    usbipd list
usbipd attach --wsl --busid <BUSID>
    2. 
        
  2. Installer les outils une fois, puis se connecter

    sudo apt-get install usbmuxd libimobiledevice-utils
curl -fL "https://github.com/xtool-org/xtool/releases/latest/download/xtool-$(uname -m).AppImage" -o xtool
chmod +x xtool && sudo mv xtool /usr/local/bin/
xtool auth login
    3. 
        
  3. Compiler l'IPA sur GitHub

    gh workflow run ios-build.yml -f environment=pprod
    4. 
        
  4. Installer sur le téléphone

    scripts/ios-install.sh --download pprod
    5. 
      

      
Apple ID gratuit : l'app expire au bout de 7 jours, et les notifications push ne fonctionnent pas. Pas de hot reload sur iPhone : itère sur Android ou Windows, et valide sur iPhone.
